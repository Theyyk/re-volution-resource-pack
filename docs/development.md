# Структура, проверки и выпуск

## Структура ресурсов

- `assets/customguimod/textures/gui/runes/` — 128×128.
- `variants/64x64/assets/customguimod/textures/gui/runes/` — 64×64.
- `pack.mcmeta` — метаданные с форматом 3.
- `VERSION` — версия набора ресурсов.
- `.github/workflows/release.yml` — проверка, сборка и публикация.

При сборке 64×64 создаётся обычная структура `assets/`, затем изображения заменяются файлами из `variants/64x64`. В ZIP нет папки `variants/`; `pack.mcmeta` и `assets/` находятся в корне. Документация и скриншоты не входят в архив.

`tools/resize-runes.ps1` перезаписывает изображения основного варианта, по умолчанию до 128×128. Он не создаёт вариант 64×64 автоматически. После изменения изображений нужна отдельная проверка обоих разрешений и отображения в игре.

## GitHub Actions

Автоматизация `.github/workflows/release.yml` запускается при:

- отправке изменений в `develop`;
- отправке тега `v*`;
- ручном запуске `workflow_dispatch`.

Отправка изменений в рабочие ветки `feature/*` не запускает сборку автоматически.

Автоматизация проверяет:

- наличие `pack.mcmeta`;
- наличие `VERSION`;
- обе директории текстур рун;
- `pack_format: 3`;
- ровно 11 PNG в каждом варианте;
- сигнатуру PNG;
- IHDR;
- размер 128×128 и 64×64;
- формат RGBA (тип цвета 6);
- 8-битные каналы;
- соответствие тега Git значению `VERSION` для сборки по тегу.

После проверки создаются:

- `re-volution-resource-pack-vX.Y.Z-64x64.zip`
- `re-volution-resource-pack-vX.Y.Z-128x128.zip`

Также проверяется, что `pack.mcmeta` и `assets/` находятся в корне ZIP, а `build/` внутрь архива не попадает.

## Описания релизов

README содержит текущие возможности, один полный скриншот и установку. История не дублируется в README.

Для каждого выпуска обязательны два файла:

- `docs/releases/vX.Y.Z.md` — русское описание;
- `.github/release-notes/vX.Y.Z.md` — английский текст для GitHub Releases.

Английский файл использует заголовок `## RE:volution Resource Pack vX.Y.Z`, разделы `### Added`, `### Fixed`, `### Other`, `### Download` и ссылку `**Full Changelog:**`. В загрузках перечисляются фактические архивы выпуска. Русский файл описывает те же изменения и ограничения.

Автоматизация проверяет наличие обеих версий, язык и заголовки английского файла перед каждой сборкой. При публикации берётся подготовленный английский файл; автоматическая генерация описания не используется.

Локальная проверка текущих описаний:

```powershell
python .github/scripts/check-release-notes.py v1.1.0
git diff --check
```

## Порядок выпуска

1. Подготовьте изменения ресурсов и оба описания. Обновите `VERSION` для нового выпуска и согласуйте имя тега.
2. Проверьте изображения и отображение в игре согласно [визуальным заметкам](resource-pack-visual-notes.md). Отдельно указывайте результаты автоматических и ручных проверок.
3. Объедините рабочую ветку с `develop` и дождитесь успешной сборки текущего коммита.
4. Перенесите проверенный результат в `main`, затем создайте тег подготовленного выпуска.
5. Проверьте опубликованное английское описание, имена ZIP и их структуру. Удалите завершённые рабочие ветки после объединения.

Схема: `feature/* → develop → main → vX.Y.Z → GitHub Release`.

Изменение документации само по себе не требует новой версии, тега или замены архивов существующих релизов.
